# 业务层坑点清单

> 业务模块最容易踩的坑(协议层 / 行为层 / 数据层 / LLM 层 / 测试层) 。
> 每条都给出"原因 + 触发条件 + 怎么回避"。修代码前先回这里查一下。

## 协议层(M 系列, 改不了服务端)

### M-1 鱼塘 `toUsers` 私聊实际是广播

- **现象**: `sendAction('CHAT', { content, toUsers: [user] })` 只带目标标记, 实际是广播给所有客户端。
- **后果**: 别在回复里发敏感信息(密码 / token / 个人隐私 / 文件本地路径)。
- **回避**:
  - 持久记忆默认关(`ENABLE_MEMORY=0`), 不要默默开起来;
  - `sendup` 即便设密码也只防君子 —— 链接分享给谁就谁能下;
  - 调试时只在 `@提及` 流里跑敏感场景。

### M-2 鱼塘协议无房主 / 成员校验

- **现象**: `close_room` / `GAME_ROOM + msgType:ROOM_CLOSE` 服务端**不校验发起者是不是房主**, 任意用户传 `roomId` 都能关任意房间。
- **后果**: chat 里被诱导 / 用户主动误用 → 别人房间被关, 体验差且无回滚。
- **回避**:
  - 工具描述里**必须**标 ⚠ 警告用户;
  - 上层加一层白名单: owner = 房主时放行, 否则需二次确认;
  - 不要批量调用, 限制 QPS; 日志里打印发起者 + 房间号便于事后追溯。
- **验证**: `test/verify-close-room.mjs` 必须连真实鱼塘才能复现 → 见 T-1。

### M-3 鱼塘预发封禁新登录 IP

- **现象**: 风控会主动拉黑新连接 IP(只拦新登录, 不踢已建立会话)。
- **后果**: 一旦断开重连就可能因 IP 被封失败, 看起来"莫名掉线"。
- **回避**:
  - 需要稳定出口(代理 IP 不变 / NAT 长期保持);
  - 被封后只能找塘主清黑名单或换出口;
  - 设计长连接心跳(本 agent 已有 90s 僵死看门狗 + 自动重连, 但封 IP 也救不回来)。

### M-4 鱼塘无房间快照协议

- **现象**: 服务端**不会主动推全量房间列表**, 只有 `GAME_ROOM_CREATED`(全服广播)和 `GAME_ROOM + msgType:ROOM_CLOSE`。
- **后果**: `activeRooms` 是订阅式累积, agent 启动前已存在的房间**不会被发现**; 准确性受在线时长约束。
- **回避**:
  - `list_rooms` 工具的 note 要明说这一点(已加);
  - 后端如果有"全量房间查询" API(M-2 协议), 应优先用 API 拉一次快照再合并订阅增量;
  - 不要把"房间总数"作为业务决策依据 —— 准时但不全。

## 行为层(B 系列, 改 agent 自己)

### B-1 回复上限 200 字符

- **现象**: 服务端单条聊天消息上限实测 200 字符, 超长会被截断或拒发。
- **回避**:
  - 统一走 `lib/reply.mjs` 的 `makeReplySender`, 内部按 `MSG_MAX_LEN` 自动分片;
  - 续段前缀用 `↪`, 优先在行边界切(`##` / `-` / 段落), 单行超长才在可读标点切;
  - 系统提示词要求模型输出**短行 / 短段**, 否则分片后难看。
- **限制**: 分片不解决单条 token 上限(只是字符); 真要发长内容用 `send_file` 走链接。

### B-2 中文词 / emoji 不可切碎

- **现象**: 在 UTF-8 字节数组上做 `slice(maxLen)` 会把一个中文词或 emoji(实际是 3-4 字节代理对)从中间切开, 显示成 `??` / 黑方块。
- **回避**:
  - 切片按 CodePoint / 字符计数, 不要按字节;
  - emoji 检测相邻高低代理对, 一对不拆;
  - 测试用例覆盖: 在 199 / 200 / 201 / 199.5 字符边界反复试。

### B-3 同用户连续指令被跳过

- **现象**: per-user `tryLock` —— 同一用户已有 in-flight 锁时, 后续消息**直接跳过**(不排队), 看起来"机器人不理我"。
- **后果**: 用户连发 `/大黄鱼 ping` + `/大黄鱼 状态` 只处理第一条; LLM 慢(8s)时尤其明显。
- **回避**:
  - 命令路由前提示 "上一轮处理中, 跳过" 加到日志(已有);
  - 用户感到困惑时让他稍等; 不要把 `tryLock` 改回全局锁(那会让不同用户也被串行化);
  - 真要排队用 `acquire`(串行但慢), 不与 `tryLock` 混用。

### B-4 `replaySkipMs` 内的消息是登录回放

- **现象**: 登录成功那一刻服务端可能重发历史消息; `liveSince > 0 && Date.now() - liveSince > opts.replaySkipMs`(默认 2s)才视为 live, 否则跳过。
- **回避**:
  - 不要改小 `replaySkipMs`(像设 0); 否则回放消息被当成新指令处理 → 误触工具;
  - 调高(5s+)保守安全, 代价是真实消息偶尔被跳过 5s。

### B-5 `replyCooldownMs` 全局防刷

- **现象**: `lastReply` 是全局时间戳, 任何回复都重置; 防刷但会让不同用户互相影响。
- **回避**:
  - 默认 4s, 别调太小(1s)否则 LLM 计算中就被冷却触发"跳过";
  - 真实业务上是 LLM 自己慢(8s+)起到了防刷, 这个 cooldown 主要是日志和 UX 保险。

### B-6 子智能体嵌套深度限制

- **现象**: `delegate` 工具检查 `extra.depth >= ctx.subagentDepth`(默认 1); 子智能体里再调 `delegate` 直接拒绝。
- **回避**:
  - 默认不开深度; 真有多层需求改 `SUBAGENT_DEPTH=2`, 但要警惕 LLM 失控递归;
  - 子智能体拿不到 `delegate`(`explore`/`math` 的 `tools` 白名单不含) → 实测嵌套被工具有效拦截, 不靠 depth 检查;
  - depth 是兜底, 不是主防线。

### B-7 触发器主动消息刷屏风险

- **现象**: `ENABLE_TRIGGER=1` 时, 累计 `TRIGGER_THRESHOLD`(默认 10)条**非自己**消息后, LLM 生成一条"有争议"消息全服广播; 重置 + 冷却。
- **风险**: 阈值太低会刷屏, LLM 输出无槽点时也要"硬凑存在感"会惹人烦。
- **回避**:
  - 默认关(已有), 开启前先调高阈值到 30+;
  - 系统提示词明令"窗口无槽点 → 空串静默"(已加);
  - 加空串 / 标点 / "路过 / 沉默"等兜底正则(已加);
  - 调试时盯 `pondState.roomLog` 看批量和频率。

## 数据层(D 系列, 改存储 / 状态)

### D-1 dotenv 不覆盖已存在的环境变量

- **现象**: 当前 shell 已经 `export FOO=1` 后再读 `.env`, 不会覆盖; 改 `.env` 看不到效果。
- **回避**:
  - 测试时先 `unset` 相关变量;
  - 实现 / 文档明确这是 "dotenv 默认行为"; 如要覆盖改用 `dotenv.config({ override: true })`(本项目未启用, **不要随便开**);
  - 用户改 `.env` 后报错时, 第一件事是检查 env 是否被 shell 缓存。

### D-2 bool 转换严格: 仅 `'1' / 'true' / 'yes'` → true

- **现象**: `loadConfig` 把字符串环境变量解析为 bool 时只认上述三个(大小写不敏感); `'on' / 'y' / 'enable' / 'enabled'` 一律 false。
- **后果**: 看着"我开了"实际是关; `ENABLE_TRIGGER=on` 用户以为开了结果沉默。
- **回避**:
  - 文档只列官方承认的三种写法;
  - 用户报"功能没生效"时第一查环境变量值, 第二查拼写;
  - 调试日志里把解析后的 bool 打出来(`log` 行)。

### D-3 `proxyPort=0` 直连

- **现象**: `PROXY_PORT=0` 表示**走直连**而非"端口为 0"; 解析为 0 时 ws-client 直接 `net.connect(TARGET.port, TARGET.host)`, 不走 HTTP CONNECT 隧道。
- **回避**:
  - 不要被"端口 0 是默认值"骗到; 没配代理时 PROXY_HOST 留空 + PROXY_PORT 留 0 才是直连;
  - 想"不要代理"必须同时设 `DIRECT=1` 或让 PROXY_PORT 留 0;
  - 测试本地 mock 服务端时通常就是直连(localhost)。

### D-4 持久记忆 + 聊天日志磁盘增长

- **现象**: `chat-log.jsonl` 默认 1000 条 / 单文件 < 64KB 不裁剪; 长跑会持续增长直到触发裁剪。`memory.json` 每用户最多 30 条但文件**只增不缩**(`_saveTimer` 1s 去抖全量写)。
- **回避**:
  - `CHAT_LOG_MAX` / `memory.maxFactsPerUser` 按磁盘预算调小;
  - 删用户 / 清事实要手动删文件(`memory.delete(username)` 没有);
  - 监控 `data/` 目录大小, 超过预设阈值(>50MB)主动 truncate;
  - 不要在磁盘 IO 高峰期频繁调 remember(去抖只解决突发写, 不解决总 IO)。

### D-5 schedule 默认内存

- **现象**: `Scheduler` 默认只在 `queue: Map`; 重启即丢任务(已有功能, 不算 bug)。
- **回避**:
  - 想跨重启显式 `ENABLE_SCHEDULE_PERSIST=1`;
  - 测试调度时用 `Scheduler.tick()` 手动触发, 不要 `wait(N秒)`;
  - 内存模式下 `Scheduler.stop()` 之后 `start()` 不会清空 `queue`(设计如此), 调用方负责清。

## LLM 层(L 系列, 模型 + 工具循环)

### L-1 个别模型泄漏工具调用文本

- **现象**: 某些模型(尤其没做工具调用微调的)会把 `<invoke name=... />` 或 `{"name":...}` 当纯文本输出, 不走函数调用协议。
- **后果**: 用户看到一段 XML / JSON 乱码, 工具没真正执行。
- **回避**(已有体系):
  - `lib/tool-call-parse.mjs` 检测 → 恢复成真正的工具调用 → 继续流程;
  - 解析失败时把那段文本**剥除**绝不让它落到聊天里;
  - 工具迭代超限进入"保留工具 + 收尾提示"模式, 不让模型被逼到文本里"假装调用";
  - 系统提示词明令"工具必须走函数调用, 文本形式会被忽略"。
- **别改的事**: 不要用正则硬剥所有 `<invoke>` —— 会误伤代码块示例。

### L-2 同名同参连续 3 次相同工具调用 = Doom-loop

- **现象**: 工具循环里同名 + 同参数 hash 连续 3 次 → 强制停止 + 提示"陷入重复"。
- **回避**:
  - 不要调阈值(3 → 5), 漏掉真 bug 的窗口会增大;
  - 真要重试就在参数里加时间戳 / 随机 seed 破环;
  - 调试时打印 dooms-loop 触发那一刻的最近 3 条调用, 改 LLM 提示词。
- **白名单**: `now` / `uptime` / `session_stats` 这种幂等且无参的不计入(?), 真要算则排除一下。

### L-3 LLM 强制短行 / 短段输出

- **现象**: 系统提示词 `extra` 段写明"每要点 1-2 行" 是为了配合 200 字符分片; 模型不遵守时分片后仍是超长。
- **回避**:
  - 让模型知道分片后的可读性约束(放进 system prompt, 已加);
  - 输出 markdown 时强制窄列(80 字符)效益有限, 主要靠模型自觉;
  - 真要给"长内容", 用 `send_file` 把全量发成 `.md`, 聊天里只放摘要 + 链接。

### L-4 无 API Key 时自由文本回复失败

- **现象**: 没配 `DEEPSEEK_API_KEY` 又没开 `MOCK_LLM`, 启动会有警告("自由文本回复将失败"), 但指令确定性路径仍可工作(`/大黄鱼 ping` → pong)。
- **回避**:
  - 启动时告警已加, 不要静音;
  - 测试 LLM 必须配 key; 测试非 LLM 路径可以 `MOCK_LLM=1`;
  - fallback 兜底已经会回 "这个我暂时答不上来, 换个问题试试?", 别改成"AI 在升级中"骗人。

### L-5 触发器 LLM 无槽点静默

- **现象**: 触发器系统在空段(全是正常闲聊无争议)时让模型输出空串, 不广播。
- **回避**:
  - 空串 / 只有标点 / `"路过|算了|沉默|闭嘴"` 一律静默(正则已加);
  - 调试时**关掉**这个兜底(L-5 关闭)的入口是日志里 `[主动] 窗口内无槽点, 保持沉默`;
  - 真要刷存在感就把阈值调高 + 系统提示词放开"可以轻度调侃"。

## 测试层(T 系列, 改测试策略)

### T-1 真实环境验证脚本不进 `npm test`

- **现象**: `test/verify-close-room.mjs`(M-2 复现)、`test/verify-list-rooms.mjs`(在线时长对 activeRooms 准确性的影响)都**必须连真实鱼塘**, 会修改真实房间状态。
- **回避**:
  - `npm test` 跑的是 `mock-server.mjs` + 单元, 不连真实鱼塘;
  - verify-* 脚本单独 `node test/verify-*.mjs`, 用前**必须**确认鱼塘环境是测试服;
  - verify-* 写日志到 `data/`, 不污染 `chat-log.jsonl`;
  - CI 永远不要跑 verify, 后果严重。

## 速查: 新增 / 修改前的自我提问

1. 这个改动走 `lib/reply.mjs` 吗? 没走 → B-1 / B-2 风险。
2. 这个数据有没有跨重启保证? 有 → D-4 风险。
3. 这个 bool 字段从环境变量读吗? 是 → D-2 风险。
4. 这个工具能让用户滥用吗? (close_room / send_file / remember) → 配上限 + 描述警告。
5. LLM 会失控循环吗? → L-2 把守。
6. 测试走 mock 还是真连? → T-1。
7. 改完有更新 `data-model.md` / 本文件 / `.claude/docs/_progress.md` 吗? → 没改文档等于没写。
